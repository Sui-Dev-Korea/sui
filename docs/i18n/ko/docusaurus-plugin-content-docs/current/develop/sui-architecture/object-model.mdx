Object는 네트워크의 기본 storage 단위이다. 온체인의 모든 resource, asset, data 조각은 객체이다. 다른 많은 블록체인은 key-value store를 포함하는 account를 중심으로 storage를 구성한다. Sui의 storage는 온체인에서 고유 ID로 addressable한 객체를 중심으로 구성된다.

모든 객체에는 다음 component가 있다:

- 전역적으로 고유한 ID.

- address 또는 객체일 수 있는 owner.

- 객체가 변경될 때마다 증가하는 version number.

- 객체를 마지막으로 사용한 트랜잭션의 digest 같은 메타데이터.

## Object type

Object에는 세 가지 type이 있다:

- **Sui 객체:** 모든 resource, asset, data 조각이다. Sui 객체는 트랜잭션이 상호작용하는 대상이며 모든 온체인 state의 building block이다.

- **Sui Move 객체:** Move language를 사용해 정의된 객체이다. Move 객체를 만들려면 `sui::object::new`를 사용해 struct를 만들어야 한다. 이 struct는 `key` ability를 가져야 하며, 첫 번째로 정의된 필드로 `id: UID` 필드를 포함해야 한다. 이 struct는 integer와 address 같은 primitive type, 다른 객체, 객체가 아닌 struct도 포함할 수 있다. 이 struct는 Sui 객체로 온체인에 저장될 수 있다.

- **Sui Move 패키지:** 다른 객체를 조작할 수 있는 스마트 계약이다. 각 Move 패키지는 Sui Move bytecode 모듈의 집합이다. 패키지 안의 각 모듈은 포함하는 패키지 내에서 고유한 name을 가진다. 패키지의 onchain ID와 모듈 name의 조합이 모듈을 고유하게 식별한다. Sui에 스마트 계약을 publish할 때 패키지가 publish 단위이다. 패키지 객체를 publish한 후에는 immutable이 되며 변경하거나 제거할 수 없다. 패키지 객체는 이전에 Sui에 publish된 다른 패키지 객체에 의존할 수 있다.

## Object 참조

Object는 다음으로 참조할 수 있다:

- **ID:** 객체의 전역적으로 고유한 ID이다. 객체의 current state를 query하거나 두 address 사이에서 어떤 객체가 transfer되었는지 설명할 때 유용한, 변경되지 않는 stable identifier이다.

- **Versioned ID:** (ID, version) pair이다. 객체 history의 특정 시점에서 객체의 state를 설명하며, 과거 특정 시점의 객체 값이 무엇이었는지 묻거나 객체가 얼마나 최근에 update되었는지 판단할 때 유용하다.

- **Object reference:** (ID, version, 객체 digest) triple이다. 객체 digest는 객체의 content와 메타데이터 hash이다. 객체 reference는 객체 history의 특정 시점에 대한 authenticated view를 제공한다. Transaction은 객체 입력이 객체 reference를 통해 지정되도록 요구하여 트랜잭션 sender와 트랜잭션을 처리하는 validator가 객체의 content와 메타데이터에 동의하도록 보장한다.

## Object ownership 개요

모든 객체에는 트랜잭션에서 누가 사용할 수 있는지를 결정하는 owner 필드가 있다. 이 필드에는 다음 option 중 하나가 들어갈 수 있다:

- **[Address owned](/develop/objects/object-ownership/address-owned):** 특정 signature scheme에서 파생된 account address 또는 object ID인 특정 32-byte address가 소유한다.

- **[Immutable](/develop/objects/object-ownership/immutable):** 누구도 소유하지 않으므로 누구나 사용할 수 있다. mutate, transfer, delete할 수 없다.

- **[Party](/develop/objects/object-ownership/party):** [`sui::transfer::party_transfer`](/references/framework/sui_sui/transfer#sui_transfer_party_transfer) 또는 [`sui::transfer::public_party_transfer`](/references/framework/sui_sui/transfer#sui_transfer_public_party_transfer) function을 사용해 transfer되며, transfer 대상 `Party`가 접근할 수 있다. Party object는 단일 소유일 수 있지만, address-owned object와 달리 consensus로 versioning된다.

- **[Shared](/develop/objects/object-ownership/shared):** [`sui::transfer::share_object`](/references/framework/sui_sui/transfer#sui_transfer_share_object) function을 사용해 ownership이 shared되며 누구나 접근할 수 있다.

- **[Wrapped](/develop/objects/object-ownership/wrapped):** 한 `struct` type이 다른 type 안에 nested된 data structure이다.

## Object 메타데이터 개요

모든 객체에는 다음 메타데이터가 있다:

- **32-byte globally unique ID:** 객체를 만든 트랜잭션의 digest와 트랜잭션이 생성한 ID 수를 encoding한 counter에서 파생된다.

- **8-byte unsigned integer version:** object를 [modify](/develop/objects/versioning)하는 모든 transaction마다 monotonically increase한다.

- **32-byte 트랜잭션 digest:** 이 객체를 output으로 포함한 마지막 트랜잭션을 나타낸다.

- **32-byte owner field:** 이 object에 [access](/develop/objects/object-ownership)할 수 있는 방식을 나타낸다.

공통 metadata 외에도 object에는 [Binary Canonical Serialization (BCS)](https://docs.rs/bcs/latest/bcs/)로 encoding된 payload를 포함하는 category-specific, variable-sized contents field가 있다:

- Move 객체는 Move type, 객체가 `public_transfer`를 사용해 transfer될 수 있는지 여부, 그리고 필드를 포함한다.

- Move 패키지는 패키지의 bytecode 모듈, 패키지의 각 type을 도입한 패키지 version을 식별하는 table(type origin table), 그리고 각 transitive dependency를 사용할 특정 패키지 version에 mapping하는 table(linkage table)을 포함한다.

## 트랜잭션-객체 DAG: 객체와 트랜잭션의 관계

Transaction은 object를 input으로 받아 이 input을 read, write, mutate한 다음 mutated object 또는 새로 created object를 output으로 만든다. 각 object는 자신을 output으로 만든 마지막 transaction의 hash를 알고 있다. object와 transaction 사이의 관계를 표현하는 자연스러운 방법은 [directed acyclic graph (DAG)](https://en.wikipedia.org/wiki/Directed_acyclic_graph)이다. 이 graph에서 node는 transaction이고, transaction `A`의 output object가 transaction `B`의 input object이면 directed edge가 transaction `A`에서 transaction `B`로 향한다. Edge에는 해당 object의 reference가 label로 붙으며, 이 reference는 `A`가 만든 object의 정확한 version과 `B`가 사용한 version을 지정한다.

이 DAG의 root는 입력을 받지 않고 system initial state에 존재하는 객체를 만드는 genesis 트랜잭션이다. 아직 committed 트랜잭션이 consume하지 않은 mutable 트랜잭션 output을 식별하고, 이 output과 선택적으로 immutable 트랜잭션 output을 입력으로 받는 새 트랜잭션을 보내 DAG를 확장할 수 있다.

Live 객체는 트랜잭션의 입력으로 사용할 수 있다. Sui가 유지하는 global state는 이러한 객체 전체로 구성된다. 특정 Sui address `A`의 live 객체는 `A`가 소유한 모든 객체와 system의 모든 shared 및 불변 객체이다.

이 DAG가 system의 모든 committed 트랜잭션을 포함하면 system state와 history에 대한 완전하고 cryptographically auditable한 view가 된다. 또한 위 scheme을 사용해 트랜잭션 또는 객체 subset의 relevant history DAG를 구성할 수 있다. 예를 들어 단일 address가 소유한 객체를 대상으로 할 수 있다.
