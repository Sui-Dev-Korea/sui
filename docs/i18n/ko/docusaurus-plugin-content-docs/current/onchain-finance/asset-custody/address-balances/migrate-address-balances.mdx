주소 잔액은 Sui 주소에 직접 연결된 대체 가능 자산을 위한 canonical balance system을 도입한다. 이는 `Coin<T>` 모델을 직접 주소 소유 잔액으로 보완하여 트랜잭션 구성을 단순화하고 코인 선택 복잡성을 없앤다.

전체 명세는 [SIP-58: Sui Address Balances](https://github.com/sui-foundation/sips/blob/main/sips/sip-58.md)를 참조한다. 주소 잔액에서 보내기, 인출, gas 지불을 구현하는 자세한 내용은 [주소 잔액 사용하기](/onchain-finance/asset-custody/address-balances/using-address-balances)를 참조한다.

## 먼저 읽기

이 rollout은 처음에는 영향 범위가 매우 제한적이다.

- deprecated되거나 제거되는 것은 없다. 현재 유효한 모든 트랜잭션은 계속 유효하다. 코인 객체가 주소 잔액으로 강제 마이그레이션되지 않는다.
- contract를 다시 작성할 필요가 없다. contract는 이전처럼 `Coin<T>`와 `&mut Coin<T>`를 계속 받을 수 있다.
- 코인은 여전히 `transfer::public_transfer` 또는 `TransferObjects` 명령를 통해 보낼 수 있다.

### 지갑, 거래소, 수탁 제공자에 미치는 영향

지갑(custodial, non-custodial, exchange 지갑)을 운영하는 모든 주체는 이 변경의 영향을 받을 수 있다. 사용자는 이제 코인 객체를 전송하는 대신 `send_funds()`를 통해 사용자의 주소로 자금을 보낼 수 있다. 지갑이 이 방식으로 자금을 받았지만 주소 잔액을 제대로 지원하지 않으면 사용자는 자금을 보거나 접근할 수 없다. 사용자는 자금을 잃었다고 생각할 수 있다. 실제로 자금이 사라지는 것은 아니지만, 영향을 받는 사용자에게 혼란을 줄 수 있다.

처음에는 ecosystem 대부분이 코인 객체 전송을 계속 사용할 것이므로 이런 일이 자주 발생하지는 않을 것이다. 하지만 특정 지갑에 주소 잔액 전송으로 자금이 도착하는 것을 막을 방법은 없으므로, 지갑 구현자는 대비해야 한다.

사용자 자금은 코인과 주소 잔액 양쪽으로 나뉠 수도 있다. Balance query(JSON-RPC, gRPC, GraphQL)는 합산 total을 표시한다. 주소 잔액 부분이 포함된 자금을 보내려면 다음 중 하나를 사용해야 한다.

- TypeScript SDK(v2+)의 `coinWithBalance`를 사용한다. 이 방식은 두 source에서 자동으로 인출한다.
- [주소 잔액 사용하기](/onchain-finance/asset-custody/address-balances/using-address-balances)에 설명된 manual 출금 logic을 구현한다.

## 잔액 쿼리 변경 사항

Balance query response는 이제 코인 객체 total과 함께 주소 잔액 정보를 포함한다.

### JSON-RPC

`suix_getBalance`와 `suix_getAllBalances` method는 이제 `fundsInAddressBalance` 필드를 반환한다. `totalBalance` 필드에는 코인 객체와 주소 잔액 자금이 모두 포함된다.

```json
{
	"coinType": "0x2::sui::SUI",
	"coinObjectCount": 2,
	"totalBalance": "99998990120",
	"lockedBalance": {},
	"fundsInAddressBalance": "5000000"
}
```

코인 기반 잔액만 얻으려면 `fundsInAddressBalance`에서 `totalBalance`를 뺀다.

### gRPC

`GetBalance`의 `ListBalances`와 `StateService` method는 이제 코인 잔액과 주소 잔액을 별도 필드로 반환한다.

- `coinBalance`: 코인 객체에 보관된 total.
- `addressBalance`: 주소 잔액에 보관된 amount.
- `balance`: 두 값의 합계.

```json
{
	"balance": {
		"coinType": "0x2::sui::SUI",
		"balance": "99998990120",
		"addressBalance": "5000000",
		"coinBalance": "99993990120"
	}
}
```

### GraphQL

주소 타입의 `balance`와 `balances` 필드는 이제 `addressBalance`, `coinBalance`, `totalBalance` 필드를 포함한다. 전체 schema는 [GraphQL Reference - `IAddressable.balance`](/references/sui-api/sui-graphql/beta/reference/types/interfaces/iaddressable)를 참조한다.

## 체크포인트 데이터에서 잔액 계산 변경 사항

가능하면 JSON-RPC 또는 gRPC가 제공하는 잔액 changes를 사용한다.

checkpoint data에서 잔액 changes를 계산한다면 이제 코인 객체 diff 외에도 `TransactionEffects`의 accumulator event를 처리해야 한다.

Sui 프레임워크는 이 과정을 위한 helper를 제공한다.

```rust
use sui_types::balance_change::{derive_balance_changes, BalanceChange};

let balance_changes: Vec<BalanceChange> = derive_balance_changes(
    &effects,
    &input_objects,
    &output_objects,
);
```

각 `BalanceChange`는 주소, 코인 타입, signed amount(사용하면 음수, 받으면 양수)를 포함한다.

전체 algorithm은 [레퍼런스 구현](https://github.com/MystenLabs/sui/blob/e23cc4bb0215ec065785a19772f22eda8ada14ae/crates/sui-types/src/balance_change.rs#L86)을 참조한다.

### accumulator event 접근

Accumulator event는 `TransactionEffects`에 embedded되어 있다. `TransactionEffectsAPI` trait를 통해 접근한다.

```rust
use sui_types::effects::TransactionEffectsAPI;

let events = effects.accumulator_events();
```

각 event는 target 주소, 잔액 type, operation(`Split`은 출금, `Merge`는 예치), amount를 포함한다. 전체 API는 [sui-types/src/effects/mod.rs](https://github.com/MystenLabs/sui/blob/main/crates/sui-types/src/effects/mod.rs)를 참조한다.

## 이전 버전과의 호환성

기존 contract와 클라이언트는 모두 계속 동작한다. 다음 섹션은 무엇이 바뀌고 무엇이 동일하게 유지되는지 설명한다.

### 기존 contract

`Coin<T>` 또는 `Balance<T>`를 받는 contract는 변경 없이 계속 호출할 수 있다. `redeem_funds` 함수(`sui::coin` 및 `sui::balance` 모듈 각각)은 PTB 안에서 출금을 예상 type으로 변환한다. 예:

```
inputs: [withdrawal<0x2::sui::SUI>(100)]
commands:
0: 0x2::coin::redeem_funds(inputs(0))
1: 0x2::transfer::public_transfer(result(0))
```

### Legacy 클라이언트

JSON-RPC compatibility layer는 주소 잔액 reservation을 나타내는 synthetic 코인 객체를 제공한다. 이는 업그레이드할 수 없는 클라이언트를 위한 기본 기능을 보존하지만, 새 개발에서는 의존하지 않아야 한다.

## 기존 코인을 주소 잔액으로 변환

Migration은 선택 사항이다. SDK는 필요에 따라 코인 또는 주소 잔액을 자동으로 선택한다. 기존 코인 객체를 주소 잔액으로 consolidate하려면 usage guide의 [기존 Coin을 주소 잔액으로 변환](/onchain-finance/asset-custody/address-balances/using-address-balances#converting-existing-coins-to-address-balances)을 참조한다.
